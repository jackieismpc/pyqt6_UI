## 0. 任务回顾

对透明规则晶体做体积估计。晶体形状约定为**长方体 + 四棱锥（屋顶形）**，由 4 个尺寸参数决定：

```
length (L)  宽度方向前沿长度
width  (W)  侧向深度
body_height (Hb) 长方体高度
pyramid_height (Hp) 四棱锥高度
体积 V = L * W * (Hb + Hp/3)
```

（该公式在现有代码里已固定：`geometry_fit.py:424` 与 `stage1_contour_recovery.py:3337`。）

晶体是**生长过程**、每次**只拍一个晶体**，因此全流程强制**只对画面中最大的那个晶体**建模。

流程分两阶段：

- **第一阶段（像素域，本次要执行）**：从视频/图片提取晶体轮廓边缘 → 拟合「长方体 + 四棱锥」线框 → 输出像素域标准几何 + 体积（px³，仅供相对比较）。
- **第二阶段（公制域，本次只搭框架）**：用标定参数把像素几何恢复到真实尺度 → 输出真实边长与真实体积（m³）。

## 3. 第一阶段详细方案（本次执行）

### 3.1 新增：可插拔深度边缘前端 `deep_edge.py`

- 主模型 **PiDiNet**（ICCV'21）：轻量、CPU 友好、无需微调即可泛化，边缘图比 Canny 干净得多，对反光/纹理噪声鲁棒。
- 落地方式：走 **`controlnet_aux`** 包（`PidiNetDetector` / `HEDdetector`），首次运行从 HuggingFace 自动下载权重（PiDiNet 权重约 2–3 MB）并缓存；无需手动放权重。
- 备选：`HED`（同包）、`DexiNed`（有 GPU 时用，走 kornia，可选）。

接口（新文件）：

```python
# deep_edge.py
@dataclass
class DeepEdgeConfig:
    backend: str = "pidinet"      # pidinet | hed | dexined
    device: str = "cpu"
    input_max_side: int = 1024    # CPU 上先缩放再推理，最后放回原分辨率
    threshold: float = 0.10       # 概率图二值化阈值(用于喂 Hough)
    hf_repo: str = "lllyasviel/Annotators"

class DeepEdgeDetector:
    def is_available(self) -> bool: ...
    def detect(self, image_bgr) -> np.ndarray:      # 返回 float32 概率图 [0,1], 原图分辨率
    def detect_binary(self, image_bgr) -> np.ndarray # 返回 uint8 0/255
```

- **懒加载 + 优雅降级**：`controlnet_aux` 未装或下载失败时，`is_available()` 返回 False，前端自动回退到增强版 Canny，并在结果里记录 warning，绝不静默出错。

### 3.2 新增：低光/强反光预处理 `_enhance_lowlight()`

放在 `stage1_contour_recovery.py`，边缘计算前调用：

1. CLAHE（现有已用，保留）
2. gamma 提亮（`--lowlight-gamma`，默认 0.6，暗图自动触发）
3. 可选多尺度 Retinex（`--use-msr`，默认关）
4. 高光/镜面抑制：对超过高光分位的像素做局部压制，避免高光轮廓被误当作物体棱线

自动触发：整图平均亮度低于阈值（`--lowlight-auto`，默认开）时启用，避免影响清晰影棚图。

### 3.3 边缘融合与注入点

- 大图/单图主路径 `_extract_fullframe_hough_segments`（`stage1_contour_recovery.py:1219`）当前是 `CLAHE→Canny→HoughLinesP`。改造为先算 `edge_backend` 指定的边缘图：
  - `canny`：保持现状（兼容旧行为）。
  - `pidinet/hed/dexined`：深度概率图二值化后，与 Canny **按位或融合**（`--fuse-canny`，默认开），再喂 Hough。深度边缘负责补齐反光处断裂的主棱线，Canny 负责保留锐利细边。
- ROI/小晶体路径 `_build_edge_map`（`stage1_contour_recovery.py:505`）同样接入融合边缘，用于 SAM2 提示框的边缘凸包细化。
- 边界抑制、Hough 参数沿用现有逻辑。

### 3.4 多后端择优（auto）

`--edge-backend auto`（默认）时：分别用 `canny` 和 `pidinet(+canny)` 各跑一遍 `fullframe_wireframe` 候选，用现有 `_select_best_candidate`（`:425`）按（`fit_ready` → `visible_ratio` → 主棱线数 → 综合分）择优。这样清晰图不会因为引入深度边缘而变差，难图能吃到深度边缘的收益。

### 3.5 「只保留最大晶体」保证（强化并显式化）

现有已有三重保证，本方案保留并补一条：
1. SAM2 掩膜 `_post_process_mask` 取最大连通域（`segmentation_models.py:283-301`）。
2. ROI 路径按面积/中心距/边缘支持打分选单个候选（`_rank_crop_windows` / `_compute_acceptance`）。
3. 线框路径按主线族聚类锁定主结构。
4. **新增**：融合边缘 → 轮廓提取后，若出现多个候选外轮廓，显式只保留**面积最大**的一个连通域再进入线框拟合，杜绝把两个晶体/反光块拼一起。

### 3.6 稳健兜底输出（保证你这张难图一定有结果看）

现有 `fullframe_wireframe` 有严格「采用门槛」，难图可能 `fit_ready=false` 而被丢弃。新增 `--force-emit-best`（默认开）：即使门槛未过，也把**当前最优候选**落盘为 `wireframe_only` / `wireframe_overlay` / 几何预览，并在文件名/JSON 标注 `fit_ready=false`、`visible_ratio`，方便你判断质量而不是拿不到图。

### 3.7 第一阶段输出（映射到你要的三张图）

对单图输入（你上传的图会走 `fullframe_wireframe` 大目标路径），输出目录里：

| 你的需求 | 产物文件 |
|---|---|
| **轮廓提取图** | `wireframes/<name>_wireframe_only.png`（拟合棱线，小目标自动紧裁放大）+ `debug/<name>_edge_map.png`（融合后的边缘证据） |
| **overlay 图** | `wireframes/<name>_wireframe_overlay.png`（棱线叠加回原图） |
| **重建几何体图** | `geometry/standard_geometry_pixel_preview.png`（标准长方体+四棱锥 3D 预览，标注 L/W/Hb/Hp 与 volume_px³）+ `.obj` + `.json` |

辅助：`masks/`、`structured/`、`consensus/`、`structured_comparison_sheet.png`、`result_summary.json`。

### 3.8 第一阶段新增 CLI（在 `stage1_contour_recovery.py`）

```
--edge-backend {auto,canny,pidinet,hed,dexined}   默认 auto
--fuse-canny / --no-fuse-canny                    默认融合
--deep-edge-threshold FLOAT                       默认 0.10
--deep-edge-input-max-side INT                    默认 1024（CPU 提速）
--enhance-lowlight / --no-enhance-lowlight        默认 auto
--lowlight-gamma FLOAT                            默认 0.6
--use-msr                                         默认关
--force-emit-best / --no-force-emit-best          默认开
```

现有参数（ROI 尺度、SAM2 提示框、验收阈值、`--scale-reference-*`、`--gt-*` 等）全部保留。

## 4. 第二阶段框架（本次只搭建，不执行）

**为什么不执行**：把像素几何恢复成真实公制体积，需要「像素 ↔ 米」的尺度基准。单目下有两条路：
- 已知一条真实边长（scale anchor）→ 现在就能算，但你没提供真实边长；
- 参考板外参 + 多视角联合拟合 → 你目前只标了内参、没标外参。

所以第二阶段**只落地接口与骨架**，并在缺外参/缺尺度基准时给出清晰报错，不产出可能误导的体积。

### 4.1 新增 `stage2_metric.py`

```python
@dataclass
class Stage2Config:
    camera_calibration: str            # 内参 JSON（有）
    mode: str = "auto"                 # auto | scale_anchor | extrinsic_multiview
    # scale_anchor 模式
    scale_reference_edge: str = "length"   # length|width|body_height|pyramid_height|total_height
    scale_reference_value: float | None = None
    metric_length_unit: str = "cm"
    # extrinsic_multiview 模式（框架）
    turntable_config: str | None = None    # 外参/参考板配置（暂无）
    angles_file: str | None = None
    expected_volume_min_m3: float = 0.1
    expected_volume_max_m3: float = 1.5

def run_stage2(stage1_geometry_json: str, config: Stage2Config) -> dict:
    """
    模式A scale_anchor（框架+可跑）：读 standard_geometry_pixel.json → 用一条已知真实边长
        换算 unit_per_px → 输出真实 L/W/Hb/Hp 与真实体积 m³。
    模式B extrinsic_multiview（框架，缺外参不跑）：
        校验 turntable_config/angles 是否齐备；齐备则调用 geometry_fit.fit_geometry；
        不齐备则抛清晰错误：'第二阶段公制多视角拟合需要外参（参考板位姿），当前缺失'。
    """
```

- **复用**：把 stage1 里的公制换算数学（`_build_metric_geometry_payload`, `_compute_standard_crystal_volume`）抽到 `metric_utils.py`，stage1 与 stage2 共用，避免两份实现漂移。
- **模式B 直接接现有后端**：`geometry_fit.fit_geometry` + `VE2.py` 的观测构建逻辑基本可平移；本次只把接口连通、加 TODO 与输入校验，等你标完外参再打开。
- 输出：`stage2_metric.json`（真实 L/W/Hb/Hp、volume_m3、尺度来源、体积范围报警占位）+ 可选 `standard_geometry_cm_preview.png`。

### 4.2 与现有 `VE2.py` 的关系

`VE2.py` 保持可用（它是「有外参时的全自动全流程」）。第二阶段框架把「公制换算」这件事独立出来，使得：
- 只有内参时 → 可做 `scale_anchor`（给一条真值边）；
- 有外参时 → 走 `extrinsic_multiview`（等价现在的 `VE2.py`，但从 stage1 几何接力，减少重复分割）。

## 5. 统一执行入口（可单跑一阶段 / 可跑全阶段）

新增 `run_pipeline.py`：

```bash
# 只跑第一阶段（像素域，本次对你的图执行这个）
python run_pipeline.py --stage stage1 \
  "<输入图/目录/视频>" \
  --output-dir stage1_runs/<name> --clean-output
  # 透传所有 stage1 参数：--edge-backend auto 等

# 跑全阶段（第一阶段 + 第二阶段公制换算）
python run_pipeline.py --stage full \
  "<输入>" \
  --camera-calibration <内参.json> \
  [--scale-reference-edge length --scale-reference-value 40 --metric-length-unit cm] \
  [--turntable-config <外参.json> --angles-file <angles.csv>] \
  --output-dir <out>
```

- `--stage stage1`：等价直接调用 `stage1_contour_recovery.main()`。
- `--stage full`：先跑 stage1，再用产物 `standard_geometry_pixel.json` 跑 `stage2_metric.run_stage2()`；缺外参且未给尺度基准时，明确提示「第二阶段未执行：需要外参或已知真实边长」。

配套快捷脚本：`scripts/run_stage1.sh`、`scripts/run_full.sh`（封装 `conda run -n crystal ...`）。旧脚本（`stage1_contour_recovery.py`、`VE2.py`）继续可单独使用，不破坏现状。

## 9. 风险与回退

| 风险 | 应对 |
|---|---|
| `controlnet_aux`/权重下载失败 | 自动回退增强 Canny，warning 记录，不中断 |
